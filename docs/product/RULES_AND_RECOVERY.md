# 판정 및 일정 복구 기준

기준일: 2026-09-10\
상태: 구현을 위한 동작 기준. 세부 스키마와 API 계약은 별도 확정.

## 판정의 단위

판정 대상은 장소 자체의 영구적 허용 여부가 아니라 **반려견 일행 × 선택한 장소·구역·서비스 × 방문 일시 × 준비 상태**다.

- 한 장소에서도 실내·테라스·특정 객실의 조건은 다를 수 있다.
- 반려견별 제한과 일행 전체 제한을 모두 적용한다.
- 방문 가능 여부, 예약·좌석 확보, 실제 현장 입장은 같은 개념이 아니다.
- 알려진 조건을 충족했다는 결과를 입장 보증으로 표현하지 않는다.

## 네 가지 상태

| 상태 | 기준 | 다음 행동 |
|---|---|---|
| 이용 가능 | 선택한 이용 방식에 필요한 조건이 충분히 확인되고 충족됨 | 근거와 충족 조건 확인 |
| 준비 필요 | 확정된 규정에 대해 해결 가능한 요구사항이 남음 | 준비물·예약·지불 등 필요한 행동 수행 |
| 확인 필요 | 관련 정보 누락, 모호한 표현, 출처 충돌, 적용 여부 불명확 | 필요한 항목만 확인하거나 다른 후보 검토 |
| 이용 불가 | 현재 반려견·시간·이용 방식이 명확한 제한을 위반함 | 이용 방식·시간 변경 또는 대체 장소 검토 |

### 대표 상태와 세부 결과

조건별 결과를 먼저 계산한 뒤 대표 상태를 정한다.

1. 현재 선택한 이용 방식에 적용되는 명확한 위반이 있으면 이용 불가.
2. 위반이 없지만 판단에 필요한 조건이 미확정이면 확인 필요.
3. 필요한 정보는 확인되었고 완료 가능한 준비만 남으면 준비 필요.
4. 필요한 조건과 준비가 모두 충족되면 이용 가능.

대표 상태가 다른 문제를 지우지 않게 한다. 체중 제한 위반과 예약 미확인이 동시에 있으면 둘 다 표시한다. 조건을 하나 해결한 뒤 모든 조건을 다시 평가한다.

OR로 연결된 허용 경로는 각각 평가한다. 실내 경로의 위반이 테라스까지 장소 전체 불가로 확장되지 않도록 한다. 사용자가 다른 경로를 선택하기 전에는 현재 계획을 자동 변경하지 않는다.

## 누락과 불확실성

- 빈 필드는 제한 없음이 아니다.
- 원문에 없는 체중·마릿수·요금·예약 조건을 생성하지 않는다.
- 사용자가 입력하지 않은 정보도 자동 충족으로 처리하지 않는다.
- 선택한 이용 방식에 관련된 조건의 누락을 평가한다. 모든 장소에 무관한 조건까지 일률적으로 요구하지 않는다.
- 어떤 항목이 해당 업종·이용 방식에 필요한지는 개발 초기 데이터 점검과 함께 명시한다. 불리한 결과를 피하기 위해 임의로 필수 항목을 줄이지 않는다.
- 모순되는 근거는 단순 평균이나 임의 우선순위로 합치지 않는다. 장소 일치, 적용 구역, 명시성, 확인 시점 등을 비교하고 해결되지 않으면 확인 필요로 둔다.
- 오래된 정보의 재확인 기준은 항목별로 정한다. 획일적인 유효기간을 검증 없이 사실처럼 제시하지 않는다.

## 규정 추출과 적용

흐름: **원문 확보 → 장소·출처 식별 → LLM 구조화 → 형식·근거 검증 → 결정론적 규칙 평가 → 설명 표시**.

LLM의 역할은 의미 추출이다. 최종 상태는 구조화된 규정과 사용자 입력에 대한 규칙 엔진이 결정한다.

각 규정에 필요한 정보:

| 정보 | 예시·목적 |
|---|---|
| 조건 항목 | 체중, 견종, 마릿수, 구역, 준비물, 예약, 시간 |
| 비교와 값 | 10kg 이하, 2마리까지 |
| 적용 대상 | 개별 반려견, 일행, 보호자, 객실 |
| 적용 범위 | 실내, 테라스, 특정 서비스 |
| 논리 관계 | AND, OR, 예외, 선행 조건 |
| 근거 | 원문 구절과 출처 위치 |
| 확인 정보 | 조회 시각, 원문 수정일, 별도 규정 확인 일시 |
| 처리 상태 | 정상 추출, 모호함, 충돌, 추출 실패 |

### 해석 사례

| 원문 | 처리 |
|---|---|
| 10kg 이하 | 10kg 포함 |
| 10kg 미만 | 10kg 제외 |
| 소형견 가능 | 임의 체중 기준으로 치환하지 않음 |
| 이동장 또는 유모차 | 하나를 충족하면 해당 조건 충족 |
| 이동장 및 입마개 | 둘 다 필요한 조건 |
| 팀당 2마리 | 일행 전체 마릿수 평가 |
| 객실별 상이 | 선택 객실의 규정이 없으면 확정하지 않음 |
| 일부 구역 가능 | 구역을 식별하지 못하면 전체 이용 가능으로 처리하지 않음 |

견종 제한은 명시된 원문과 사용자 입력을 기준으로 다룬다. 모호한 견종명이나 믹스를 임의 분류하지 않는다. 장소 규정과 법적 의무도 혼동하지 않는다.

### 추출 검증

- 추출한 수치·단위·조건에 원문 근거가 있는지 검사한다.
- 여러 필드에 같은 문구가 반복되면 독립적인 근거가 여러 개 있는 것으로 계산하지 않는다.
- 필드명만 믿지 않고 전체 관련 문맥과 적용 범위를 검토한다.
- LLM 오류·시간 초과·형식 실패를 이용 가능으로 대체하지 않는다.
- 같은 원문·사용자 조건·규칙 버전은 같은 판정이 나오게 한다.
- 감사에 필요한 버전·출처 정보의 보관은 데이터 제공 조건과 공모전 저장 지침 안에서 설계한다.

## 출처와 시점 표시

다음 세 시점을 구분한다.

1. **API 조회 시각**: 시스템이 정보를 가져온 시각.
2. **원본 콘텐츠 수정일**: 제공자가 콘텐츠를 수정한 날짜. 사진·주소 수정일 수도 있음.
3. **규정 확인 일시**: 해당 출입 조건을 실제로 확인한 시점. 확인 경로도 함께 표시.

오늘 조회했다는 이유로 오늘 업체가 규정을 확인했다고 표시하지 않는다. 원문에 정책 시행일·예외 기간이 있으면 방문 날짜와 대조한다.

## 일정 검증

- 날짜, 출발 시각, 장소 순서, 예상 체류시간, 이동시간으로 도착·출발 시각을 계산한다.
- 운영시간, 휴무, 휴게시간, 입장 마감은 서로 다른 조건으로 다룬다.
- 도착 시 영업 중이라는 이유만으로 예정 활동을 완료할 수 있다고 단정하지 않는다.
- 시간 원문이 모호하거나 임시 운영 여부를 알 수 없으면 확인 필요로 남긴다.
- 예약 또는 사용자가 고정한 일정은 제약으로 보존한다.
- 이동시간의 조회·예측 기준을 표시하고 확정 도착시간으로 표현하지 않는다.
- 주차·보행·대기 여유를 적용할 경우 사용자 조정값 또는 명시한 가정으로 취급한다.

## 일정 복구

### 같은 장소에서 해결

명시적인 허용 규정이 있을 때 준비물, 이용 구역, 방문 시각 변경을 검토한다. 원래 장소를 유지하는 방안이 사용자의 필수 조건을 위반하면 추천하지 않는다.

예: 실내 필수인 사용자에게 테라스만 가능한 해결안을 최종 적합안으로 제시하지 않는다.

### 대체 후보 필터와 비교

1. 반려견 조건을 만족하는가.
2. 방문 예정 시간에 이용 가능한가.
3. 원래 목적을 유지하는가.
4. 고정된 방문지·시간을 보존하는가.
5. 추가 이동시간과 변경 부담이 얼마나 작은가.

업종뿐 아니라 식사·휴식·산책·관람 등 방문 목적을 유지한다. 메뉴 확인이 없는 카페를 식사 가능한 식당으로 자동 대체하지 않는다.

확인 필요 후보는 확정 조건 충족 후보와 구분한다. 적합한 후보가 없으면 추천을 강제로 채우지 않는다.

추가 이동시간의 기본 비교:

```text
추가 이동시간 =
  시간(이전 장소 → 대체 장소) + 시간(대체 장소 → 다음 장소)
  - 시간(이전 장소 → 원래 장소) - 시간(원래 장소 → 다음 장소)
```

첫·마지막 방문지는 선택한 출발·종료 지점을 사용한다. 여러 장소가 바뀌거나 시간대에 따라 이동시간이 달라지는 경우에는 전체 코스를 재계산한다. 위 식만으로 모든 일정의 성립을 판단하지 않는다.

사용자에게는 **검토한 후보 중 일정 변화가 적은 대안**이라고 설명한다. 전역 최적해를 계산하지 않고 최적 경로를 보장한다고 표현하지 않는다.

### 대체 적용 이후

- 이후 모든 방문지의 도착·출발 시각과 관련 조건을 다시 평가한다.
- 교체로 다른 장소의 입장 마감을 넘기면 해당 문제를 표시하고 해결 완료로 처리하지 않는다.
- 변경 전후 장소, 이동시간, 남은 준비·확인 항목을 비교한다.
- 적용 취소 또는 이전 선택으로 돌아가는 경로를 제공한다.

## 준비사항과 사용자 확인

- 준비물은 요구한 장소·규정과 연결하고 같은 품목은 합쳐 표시한다.
- 일반 권장 준비물은 업체 필수 규정과 구분한다.
- 사용자 체크는 사용자 신고 상태다. 예약 시스템 연동이 없다면 예약 확정이라고 주장하지 않는다.
- 사용자 문의 답변은 본인 코스 판단에 활용할 수 있지만 다른 사용자용 공식 정책으로 자동 승격하지 않는다.
- 입장 거부 감소율·완주 확률은 현장 추적 자료 없이 생성하지 않는다.
