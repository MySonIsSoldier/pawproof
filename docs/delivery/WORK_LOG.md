## 2026-09-13 · Vercel 배포와 PWA Google 로그인

- 사용자 확인: `https://pawproof-rose.vercel.app/` 첫 배포 및 환경변수 설정 완료. 이후 검증된 변경의 `main` 푸시·Vercel 자동 배포를 에이전트가 진행하도록 승인했다.
- 배포 준비: 운영 `.env.example` 기본값·직접 입력 10개를 정리했다(`80238be`). Firebase 개발 도구의 선택적 re2 빌드 정책 누락을 수정하고 새 설치·운영 빌드를 검증했다(`204f985`).
- 제보: iPhone Safari에서 설치한 PWA의 Google 로그인 창에 키보드가 뜨지 않음. 수정 전 운영 브라우저 검사에서 OAuth 창을 열 때 앱 모달의 포커스/스크롤 잠금이 남는 것을 확인했다. 이것만으로 OS 키보드 문제의 단일 원인이 확정된 것은 아니다.
- 조치: Google 로그인 훅으로 흐름을 분리하고 팝업 전에 모달을 완전히 제거한다. Auth SDK를 준비 단계에서 로드해 클릭 중 동적 import를 없앴다. 성공 시 `/plan`·토스트, 취소/차단 시 모달 복귀를 유지한다. iOS가 창 닫기를 감지하지 못할 때를 위한 대기 종료 버튼과 재시도 경합 방지를 추가했다.
- 문서: AGENTS.md의 현재 상태·코드 품질·비밀 관리·검증·푸시/자동 배포 규칙을 갱신했다. [Firebase 계약](../engineering/FIREBASE_AUTH_AND_STORAGE.md)과 [반복 검사](../engineering/TESTING.md)에 동작과 실행법을 기록했다.

검증: 관련 Playwright 26개(기존 Firebase 18개 + Google 팝업 6개 + iOS 신호 경로 2개), 단위 91개, lint·typecheck·운영 빌드 통과. iOS 신호 검사의 최초 시간 초과는 앵커로 열린 창을 일반 popup 이벤트로 기다린 검사 오류였으며 context의 새 page 이벤트로 수정해 통과했다. 운영 점검 스크립트는 실제 Google 창을 열고 닫기만 하며 사용자 자격증명을 입력하지 않는다. 개발 미리보기는 검사 후 재시작했다.

운영 반영: 로그인 수정 `a90c3cb`와 문서 갱신 `d940bb8`을 main에 푸시했다. 이후 운영 `/sw.js`의 새 릴리스 반영과 홈 HTTP 200을 확인했다. 같은 운영 점검 스크립트에서 OAuth 창 열기 시 모달 잠금이 수정 전 `false`(해제 안 됨) → 수정 후 `true`(해제됨)로 바뀌었고 로그인 화면 복귀·닫기까지 통과했다. 실제 Google 자격증명은 입력하지 않았다.

남은 확인: 수정 배포의 새 버전으로 iPhone PWA를 다시 열고 Google 이메일·비밀번호 입력 시 OS 키보드가 표시되는지 확인한다. Chromium의 standalone/iPhone 신호와 Auth 에뮬레이터 검사는 실제 iPhone WebKit·키보드 검증이 아니다. 환경변수·Firebase authDomain은 이번 수정에서 변경하지 않는다.


## 2026-09-13 · 프로필·인천 검색 AbortSignal 호환성

- 제보와 원인: 반려견 정보·인천 장소 조회 시 `AbortSignal.any is not a function`. 계정/여행 클라이언트 요청 코드가 미지원 정적 API를 무조건 호출했다. 운영 페이지에서 `any`만 제거하고 검색을 제출해 동일 오류와 서버 검색 요청 0회를 재현했다. 사용자 기기의 OS·브라우저 버전은 확인하지 않았다.
- 수정: `src/lib/http/request-signal.ts`의 AbortController·타이머로 호출자 취소와 계정 30초/여행 290초 제한을 유지한다. 응답 본문 소비를 포함하며 완료·실패 시 타이머와 리스너를 해제한다. 프로필·계정 노트·검색·코스 검사·복구 API에 함께 적용된다.
- 검증: 단위 96개, lint·typecheck·운영 빌드, Firebase 프로필 관련 Playwright 8개 통과. 이 중 데스크톱·모바일의 반려견 등록/저장/재조회 흐름은 `any`와 `timeout`을 모두 제거했다. 수정 전 운영 검사에서 최초에는 자동 추천의 일반 오류 문구를 대상으로 삼아 단언에 실패했으며, 실제 검색 제출 뒤 원래 오류를 확인하도록 검사를 바로잡았다.
- 운영 빌드의 인천 탐색/검색·기존 노트 장소 복원 Playwright 4개도 통과했다. 수정 커밋 `ed07a24`를 main에 푸시한 뒤 운영 `/sw.js`의 새 릴리스와 `/api/health` 정상 응답을 확인했다. 같은 운영 검색 스크립트에서 수정 전 오류/요청 0회 → 수정 후 자동 추천·검색 제출 성공/합성 요청 2회로 바뀌었다. 수정 후에는 `any`·`timeout`을 모두 제거했다. 실제 계정·유료 공급자를 운영 회귀 검사에 사용하지 않았다. 실제 iPhone WebKit/PWA에서의 조회는 사용자 기기 확인이 남아 있다.

- 비회원: 코스·검사 결과는 현재 Zustand 메모리에만 유지한다. 기기 저장/불러오기/삭제 UI와 구현을 제거하고 이전 기기 기록은 읽거나 이전하지 않는다. 편집/검사 후 beforeunload 기본 확인창을 요청한다. 취소 시 입력/결과 유지, 확인 시 새로고침으로 초기화한다. 최근 검색어는 별도 기기 편의 기능으로 유지한다.
- 회원: 여행 상단의 제목 입력·자동 저장 상태·내 여행 노트·새 여행 노트로 관리한다. 제목/날짜 검색 모달과 열린 노트 표식을 제공하며 정상 전환은 변경사항 저장 후 즉시 연다. 삭제/저장 실패 초안 폐기만 확인한다. 로그인 직전의 입력 또는 검사 결과를 보존하며 로그아웃/다른 계정 전환 시 기존 편집 상태와 note URL 선택을 비운다. 복구 조회에 실패하면 미전송 초안을 유지한다.
- 문서·안내: 제품/디자인/아키텍처/데이터/인증/PWA/테스트 기준과 홈·소개·로그인·오프라인·업데이트 안내를 갱신했다. 오프라인 한국어 문구 변경으로 전용 글꼴을 재생성했다.
- 검증: 단위 95개(폐기한 기기 저장 검사 1개 제거), lint·typecheck·운영 빌드 통과. 오프라인 글꼴의 새 글자 누락을 재생성 후 관련 5개 검사로 해소했다. Firebase 프로필/자동 저장 12개 + 새 UX/계정 분리/충돌 복구 6개 통과. 새 UX 실행기의 첫 종료는 검사 성공 후 143을 반환했지만 복구 검사를 포함한 후속 실행은 정상 종료했다. 운영 브라우저는 54개 통과 후 새로고침 검사 2개의 대화상자 대기 순서를 수정해 2개 모두 재검사 통과했다(개발 전용 2개 제외). /absproxy/3101 basePath의 비회원·검색·계정 준비 검사 8개도 통과했다. 실제 외부 code-server 인증 프록시는 이 검사에 포함하지 않는다. 새로고침 직후 스크린샷의 caret 숨김 스타일이 hydration 전에 삽입되는 검사 간섭은 준비 대기와 caret 유지 옵션으로 분리했다. 변경 커밋 `12ae927`을 main에 푸시했다. 운영 `/sw.js`의 새 릴리스·`/api/health` 정상 응답을 확인했고 운영 노트 UX 스크립트에서 `/plan` HTTP 200·상단 로그인 CTA·기기 저장 제거·새로고침 취소 시 입력 유지·확인 시 초기화·모바일 폭 검사를 통과했다. 검색은 합성 응답이며 실제 계정 쓰기는 0회다. 개발 미리보기를 복원했다.
- 범위: 브라우저가 정한 기본 경고 문구를 사용한다. 사용자 정의 새로고침 모달, 모바일 강제 종료에서 항상 경고, 실제 iPhone PWA 새로고침/키보드 검증을 완료했다고 표현하지 않는다. 실제 계정·유료 공급자 회귀는 실행하지 않는다.


## 2026-09-13 · 운영 프로필·노트 API 500

- 제보: 운영 프로필 GET·개별 노트 PUT 500으로 반려견 이름/계정 노트를 저장하지 못함. 인증 정보 없는 프로필/노트 목록도 빈 본문 500이며 health는 200인 것을 직접 확인했다.
- 재현: Next 배포 추적 파일만 복사한 격리 환경은 Node 24 기본값에서 401, Vercel과 같은 require(ESM) 비활성화 시 ERR_REQUIRE_ESM을 반환했다. Firebase Admin 14.4.0 → jwks-rsa 4.1.0이 ESM 전용 jose 6.2.12를 동기 require하는 초기화 경로가 원인 후보로 확인됐다. 운영 Runtime Logs는 아직 제공받지 않았다.
- 수정: jwks-rsa의 utils/Passport 진입점을 비동기 import로 바꾸는 버전 한정 pnpm 패치. 설치 시 적용되도록 패치·workspace·lockfile을 함께 관리한다. Admin/암호화 SDK 버전과 인증 검증 정책은 유지한다.
- 회귀: require(ESM)을 비활성화한 SDK 로딩·합성 서명 키 검사와 인증 없는 6개 계정 API의 401 JSON 검사를 추가했다. 기존 에뮬레이터/운영 빌드 검증과 푸시·배포 후 결과는 아래에 기록한다.

검증: frozen-lockfile 설치, 단위 96개, lint·typecheck·운영 빌드, demo Firebase Playwright 8개 통과. 수정 후 3개 계정 라우트의 추적 파일만 각각 격리 복사하고 require(ESM)을 비활성화해 6개 메서드 모두 401 JSON을 확인했다. 전체 Next CLI에 같은 플래그를 적용한 첫 E2E 실행은 next.config.ts의 별도 로딩 경로에서 서버 시작 전에 실패했다. Vercel의 빌드/함수 실행 구분에 맞춰 모듈 제한은 위 격리 함수 검사에 적용하고 HTTP E2E는 정상 운영 실행기로 확인한다. 운영 실계정과 유료 API는 회귀에 사용하지 않았다.

운영 빌드 HTTP Playwright 2개(데스크톱·모바일)도 통과했다. 개발 미리보기는 Firebase 검사 후 복원했다.
