# 지도 중심 탐색 구현

2026-09-16 · 사용자 승인: 카카오맵, 모바일 우선 주변/여행지 탐색, 반려견 조건 필터, 부족한 정보의 문의 경로, 기존 여행 노트 연결.

- [x] 2. 카카오 JavaScript SDK 지연 로딩, 현재 위치/목적지 검색, 지도 이동 후 명시적 재검색, 모바일 목록 패널.

## 계약

`/plan`의 실제 모드는 지도로 시작한다. `view=note` 또는 여행 노트 탭은 기존 편집기를 연다. 두 화면은 하나의 PlannerProvider를 공유한다. 비회원 영구 저장은 하지 않는다. 가상 모드는 기존 코스 체험을 유지한다.

지도 후보는 KTO이며 카카오의 일반 가게를 반려동물 동반 가능 장소로 간주하지 않는다. 지도에는 좌표가 유효한 후보만 표시한다. 주변 검색은 반경 1~20km, 유형별 30건·최대 100건, 서버 동시 2회로 제한한다. 후보/빈 결과를 전국 전체 업소 현황으로 표현하지 않는다.

규정은 사용자가 장소를 선택한 시점에 해당 장소 1곳만 조회·추출하며 동시 2곳으로 제한한다. 지도 이동/필터 변경으로 LLM을 자동 호출하지 않고, 목록을 열어두는 것만으로 모든 장소를 조회하지 않는다. 조회 중에는 선택한 장소 상세에 진행 상태를 표시하고, 완료 후 활성 화면에서 현재 반려견·구역·준비물과 다시 대조한다. 지도 상태는 동반 조건에 대한 평가이며 운영시간·이동시간은 노트의 코스 검사에서 처리한다. 정보 누락·실패는 확인 필요다.

카카오 JavaScript 키는 공개 식별자이며 허용 도메인으로 제한한다. `NEXT_PUBLIC_KAKAO_MAP_KEY`를 사용하고 길찾기 REST 키와 분리한다. 키 없음/SDK 실패에도 장소 목록·노트 접근은 제공하되 가짜 지도를 그리지 않는다. 위치 권한은 내 주변 버튼 선택 시만 요청하고 위치를 계정 저장·기기 저장하지 않는다.

전화는 현재 KTO 상세에서 확보한 번호만, 카카오 장소 ID 미확보 시 상호+주소 검색 링크로 제공한다. 좌표 링크와 실제 업체 상세 페이지를 혼동하지 않는다. 문의는 사용자 복사/전화 동작이며 자동 전송하지 않는다.

공식 참고: [카카오 지도 준비·URL](https://apis.map.kakao.com/web/guide/), [지도·이벤트·서비스 API](https://apis.map.kakao.com/web/documentation/). 실 지도 검증에는 사용자 앱의 JavaScript 키·사용 설정·도메인 등록이 필요하다.

1단계 검증: typecheck·lint·관련 단위 9개·운영 빌드 통과. 실 지도/규정 표본 확인은 화면 연결 후 수행한다.

화면 검증: 단위 106개, typecheck·lint, 지도 4개와 기존 노트/코스/비회원 관련 16개 Playwright 통과. 최초 지도 검사 실패는 SDK 모형 문법 오류였으며 수정 후 4개 재실행 통과. 실제 SDK·타일·운영 도메인은 배포 후 별도 점검한다.

운영 확인(2026-09-16): 두 도메인 모두 화면·주변 API 200이지만 실제 SDK는 실패했다. 카카오 응답은 403 / `App(pawproof) disabled OPEN_MAP_AND_LOCAL service.`로 앱의 지도·로컬 서비스 활성화가 선행되어야 한다. 사용자에게 설정을 요청했으며 실제 타일 검증 전까지 4단계는 미완료로 유지한다. 기능 커밋 `660a347`, `5524d52`는 main 푸시 완료.

후속 운영 확인: 사용자 키 교체 및 재배포 후 두 도메인에서 `scripts/check-map-discovery.mjs`가 통과했다. 실제 SDK·지도 타일·마커 표시, 주변 후보 1건, 상세 카카오 검색 링크, 코스 담기→노트→지도 복귀의 상태 유지, 모바일 폭의 가로 넘침 없음을 확인했다. 각 도메인 주변 검색 2회, LLM 호출 0회. Chromium 모바일 에뮬레이션이며 실기기·실계정 저장·GPS 실제 위치·실제 규정 추출은 이번 점검 범위 밖이다.

## 2026-09-17 후속 개선

- 모바일 지도 영역을 확대하고 지도/노트 하단 내비게이션, 비모달 장소 패널, 연속 담기 후 완료 흐름을 구현했다. 기존 PlannerProvider와 계정 자동 저장 경계를 유지한다.
- 마커의 기존 숫자는 순번이며 가맹점 개수가 아니었다. 이제 장소 이름과 겹침 묶음의 `N곳`을 구분하고 모든 구성원을 표시한다. 화면 픽셀 기준으로 확대/축소 시 재그룹화하며 동일 좌표도 목록에서 각각 선택할 수 있다.
- 담은 장소는 유형·지역 검색과 독립적으로 유지한다. 방문 순서 점선, 코스 번호, 전체 영역 맞춤을 제공한다. 실제 도로 경로를 새로 조회하지 않으며 점선의 의미를 명시한다.
- hover 시 검색 버튼 가로 이동을 수정하고 반경에 공통 Select를 적용한다. 지도 아래 요약·출처와 여백을 둔다.
- 모바일 지도 도구는 검색 버튼 하나로 열고 검색·필터를 같은 drawer에서 관리한다. 장소를 누르면 해당 장소의 규정을 자동 조회하며, 선택 상세에 로딩·실패 재시도 상태를 표시한다.
- KTO 내부 필드명은 원문 검증용으로만 유지하고 사용자용 근거·준비표·원문 보기에서는 `etcAcmpyInfo:` 같은 접두사를 제거한다.
- 문의 문구는 장소를 선택했을 때 OpenRouter로 실제 발송 가능한 구어체를 생성하고, 키나 네트워크가 없으면 같은 정보를 담은 기본 문구를 표시한다. 첫 지도 중심은 서울 명동으로 고정하며 사용자가 주소 검색·지도 이동·내 주변 버튼으로 원하는 지역을 선택한다.
