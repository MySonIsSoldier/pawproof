# 2026 관광데이터 활용 공모전 개요

기준일: 2026-09-10\
참가 부문: 웹·앱 구현 부문\
현재 단계: 사용자 설명상 예비 아이디어 제출 통과 후 서비스 구현 준비

## 참가 및 지정과제

- 팀: 사용자와 생활관 선임, 총 2명.
- 출품 예정 서비스: **PawProof(포프루프) — 반려견 여행 코스 사전검증**.
- 제출 유형 계획: 웹.
- 핵심 요건: 선택 지정과제의 관광 문제를 해소하는 방향으로 기획하고, 한국관광공사 OpenAPI를 필수 활용한 완성 서비스를 제출한다.
- 지정과제는 최종 제출 시 1개만 선택한다. 다른 과제의 요소를 결합할 수 있지만 심사는 최종 선택 과제를 기준으로 진행된다.

**기획 기준 과제는 6번이다.**

> 모호한 반려동물 출입 조건 및 규정 인지 오류로 현장 입장 거부 및 헛걸음 유발 문제

공식 참고 예시는 반려동물의 세부 특성·목적지 입력, 출입 제한 규정 분석, 상세 동반 가능 여부와 준비물 안내를 제시한다. 예시대로 개발할 의무나 별도 가·감점은 없다. PawProof는 이 문제를 코스 전체 검증과 일정 복구까지 확장한다.

## 제출 항목

제출처는 한국관광 콘텐츠랩의 공모전 접수 페이지다. 참가 신청 계정으로 로그인하고 이메일 인증 후 제출한다.

| 구분 | 필요한 내용 |
|---|---|
| 팀 정보 | 팀명, 최종 팀원 정보. 팀명·팀대표 변경 불가 |
| 서비스 정보 | 서비스명, 개요, 유형, 최종 지정과제 1개 |
| 테스트 정보 | 접속 가능한 서비스 URL, 로그인 방식, 필요 시 지정 테스트 계정 |
| 공사 OpenAPI 활용 | 실제 사용한 API, 신청자별 인코딩·디코딩 인증키 일체, 대표 API 운영계정 신청 여부 |
| 기능설명서 | **제공 양식을 사용하고 PDF로 변환하여 제출** |

인증키는 공모전이 요구하는 공식 제출 경로에서만 제출한다. 공개 문서·화면 캡처·로그·저장소에 넣지 않는다.

### 로그인 방식

- 비로그인으로 핵심 기능을 사용할 수 있으면 테스트 계정 생성이 불필요하다. PawProof의 기본 계획이다.
- SNS 연동 로그인만으로 사용할 수 있는 경우에도 지정 테스트 계정 생성이 불필요하다.
- 별도 계정 로그인이 필요하면 개인 계정 대신 공모전 지정 형식의 테스트 전용 계정을 만든다.
- 공지의 일반 계정 형식: ID `openapi`, PW `2026openapi!`.
- 공지의 이메일 계정 형식: ID `openapi@메일도메인`, PW `2026openapi!`.

위 값은 공개된 심사 계정 형식이며 실제 계정이 생성되었다는 의미는 아니다.

### 기능설명서 구성

1. 서비스 소개: 명칭, 유형, 타깃, 개요, 지정과제와 선택 이유, 기획 방향, 해시태그별 기능.
2. 해시태그 연계 핵심 기능별 설명과 흐름도.
3. 서비스 대표 이미지 1장, 상세 이미지 3~5장.
4. 최종 서비스에서 사용한 한국관광공사 OpenAPI 목록.
5. 선택: 최종 사용한 기타 API·파일 데이터 목록.
6. 서비스 차별성과 발전계획.

현재 실제 양식 파일은 확보하지 않았다. 본 문서의 구성이 공식 양식을 대체하지 않는다.

## 데이터 활용 및 출처 규정

- 한국관광공사 **OpenAPI 활용이 필수**다. 파일 데이터만 사용하는 방식은 인정되지 않는다.
- 서비스 개발 기간의 실제 호출 이력과 서비스 내 사용 내용을 확인할 예정이다.
- 제공 공지는 로컬 DB 저장보다 실시간 호출을 강력히 권고한다. 부득이한 로컬 DB 저장은 별도 문의·신청을 안내한다.
- 캐시와 추출 규정의 장기 저장도 자동으로 허용된다고 전제하지 않는다. 보관 범위는 운영팀 안내에 맞춰 확정한다.
- 최신 제출 항목은 대표 API 운영계정 신청을 **선택 사항**으로 설명한다. FAQ의 일부 문장은 신청정보 제출을 더 포괄적으로 서술하므로 실제 제출 페이지·매뉴얼과 대조한다.
- 허용된 텍스트 출처 표기: `출처: ⓒ한국관광공사` 또는 `출처: ⓒ한국관광콘텐츠랩`.
- `TourAPI` 명칭만 단독으로 출처 표기하는 것은 지양한다.
- 기관이 직접 운영하는 서비스처럼 보이게 하는 명칭·표현을 사용하지 않는다. 공식 CI/BI 로고는 무단 사용하지 않는다.

## 개발·제출 방식

- 생성형 AI를 서비스 기능이나 개발 보조에 활용할 수 있다. 실제 안정적으로 동작하는 완제품이 평가의 핵심이다.
- 웹은 접속 가능한 URL을 제출한다.
- 앱은 마감 전 최소 1개 앱 스토어 등록·승인이 완료된 링크가 필요하다. 추가 등록 기간은 제공되지 않는다.
- **PWA 설치 기능만으로 앱 제출 요건을 충족한다고 보지 않는다. PawProof는 웹으로 제출한다.**
- 위치정보 관련 FAQ는 주최 측의 안내이며 개별 서비스에 대한 법적 확답이 아니다. 위치 기능을 추가할 경우 실제 데이터 흐름에 따라 검토한다. 현재 핵심 흐름은 사용자가 고른 장소의 좌표로 일정을 계산한다.

## 참가·운영 유의사항

- 동일 서비스의 다른 부문 중복 출품은 불가하다.
- 동일 서비스로 공사 관광데이터 활용 공모전 수상 또는 공사 주관 서비스 개발·구축 지원을 받은 경우 참가 제한이 있다.
- 서비스 내용과 최종 지정과제는 개발 과정에서 개선할 수 있으나 최종 제출 자료에 정확히 반영해야 한다.
- 서비스명은 변경 가능하지만 현재 사용자 결정은 PawProof 유지다.
- 최종 팀원은 사전 회원가입을 준비하고, 신청 계정의 이메일 인증 가능 여부를 미리 점검한다.
- 마감 이후 제출 자료 수정이 불가능하다.
- 심사 기간에도 URL과 핵심 기능, 외부 API 연결이 동작해야 한다.
- 서비스 소유권은 참가자에게 있으며 개발 비용 지원은 없다.
- 허위 내용, 필수 항목 누락, 양식 미준수는 심사 제외나 수상 취소 사유가 될 수 있다.
