# 무료 호스팅·비용·배포 운영

기준일: 2026-09-10\
상태: 운영 설계. 외부 계정 연결, DNS 변경, 결제 플랜 설정, 배포는 수행하지 않았다.

## 무료 운영의 범위

우선안은 **Vercel Hobby + Firestore Spark**다. 무료 제공량 안에서 호스팅·DB 비용을 0원으로 시작한다. 한도 초과 때 유료 플랜으로 자동 변경하는 계획은 없다. 무상 플랜은 서비스 지속이나 무제한 용량을 보장하지 않는다.

LLM·지도·이동시간 API는 별도 공급자 비용과 쿼터를 갖는다. 사용자는 호스팅 무료를 명확히 요구했고, LLM까지 완전 무료여야 하는지는 아직 답변하지 않았다. 유료 LLM 예산을 확정된 비용으로 넣지 않는다. 무료 LLM을 선택하더라도 구조화 추출 정확도·일일 제한·심사 기간 가용성을 실제로 검증해야 한다.

비용 한도에 도달하면 검증을 중단하거나 영향을 받은 항목을 확인 필요로 표시한다. 가짜 규정·저장된 과거 성공 결과를 현재 검증처럼 보여주지 않는다.

## 호스팅별 판단

| 구성 | 현재 판단 | 도입 전에 확인할 것 |
|---|---|---|
| Next.js + Vercel Hobby + Firestore Spark | **우선안** | Hobby 용도 조건, 공개 Org 연동, 실제 요청 시간·무료량 |
| Next.js + OpenNext + Workers Free + D1 Free | 대안 | 어댑터 호환, 요청당 CPU 10 ms, 외부 호출 제한, D1 스키마 |
| 기존 OCI + Coolify + Next.js Node + Firestore | 관리형 호스팅이 맞지 않을 때 대안 | 기존 서버 요금·자원·TLS·프로세스·백업·심사 기간 가동 |

선택 근거와 무료 DB 비교의 기준은 [스택 결정](../engineering/STACK_DECISION.md)이다. 플랫폼을 바꾸면 어댑터·배포 설정을 수정하고 다시 검사한다. 이미 구현한 코드를 아무 수정 없이 옮길 수 있다고 약속하지 않는다.

## 사용량 예산

공식 할당량을 모두 목표 사용량으로 잡지 않는다. 실제 한 코스당 API 호출·Firestore 읽기/쓰기·LLM 토큰·처리 시간을 먼저 측정한다.

| 항목 | 초기 제안 |
|---|---|
| 코스 | 3~5개 방문지 |
| 대체 후보 | 문제 지점별 최대 3개, 한 번의 복구 탐색에서 전체 최대 6개부터 시작 |
| 외부 동시 호출 | 공급자별 제한을 반영해 작은 상한부터 시작 |
| LLM | 전체 입력 길이·출력 길이·재시도 횟수에 상한. 모델과 일일 예산은 미확정 |
| 재검증 | 입력 변경 때 자동 연속 실행하지 않고 명시적 동작으로 실행 |
| 로그 | 원문·전체 URL 대신 요청 ID, 공급자, 소요시간, 상태·호출 수 집계 |

후보 수는 제품 품질과 쿼터를 측정한 뒤 조정한다. 반려견·시간 조건을 통과한 후보가 없으면 수를 억지로 채우지 않는다. 하루 100코스, 코스당 자체 DB 읽기 12회·쓰기 2회라면 1,200읽기·200쓰기라는 식으로 계산하되 이는 가정 예시이며 **KTO·LLM·경로 호출량을 포함한 실측값이 아니다.**

대체 요청에도 서버 측 입력 제한·중복 제출 방지·사용량 제한을 적용한다. 서버리스 메모리 카운터만으로 전체 사용량을 제한할 수 없으므로, 필요한 경우 Firestore 트랜잭션 등 공유 상태에서 예산을 예약·차감한다. 카운터 자체의 DB 비용과 동시성도 측정한다. IP·세션 제한만으로 남용을 완전히 막을 수 있다고 가정하지 않는다.

Firestore Spark에서 유료 TTL 삭제를 사용하지 않는다. 자체 데이터의 보관 기간과 정리는 무료 삭제 할당량 안에서 별도로 설계한다. 개발과 운영을 프로젝트로 분리할 때 각 설정·데이터를 구분하며 무료량을 우회하려는 프로젝트 증설은 하지 않는다. [Firestore 무료 할당량](https://firebase.google.com/docs/firestore/quotas)

Cloudflare 대안의 경우 Workers CPU와 D1의 읽은 **행 수**를 별도로 관찰한다. SQL 전체 스캔은 반환 행 수가 적어도 많은 읽기를 발생시킬 수 있다. 인덱스·작은 쿼리로 설계하고 실제 측정한다. [Workers 가격](https://developers.cloudflare.com/workers/platform/pricing/), [D1 가격](https://developers.cloudflare.com/d1/platform/pricing/)

## 도메인과 DNS

새 도메인은 지금 필요하지 않다. 개발·초기 배포는 플랫폼 기본 주소로 시작할 수 있다. `pawproof.hothyun.com`은 사용자가 선택할 수 있는 기존 도메인의 서브도메인 예시이며 아직 사용을 확정하거나 설정하지 않았다.

- **Vercel 선택 시:** Vercel에 결정한 도메인을 등록한 뒤 대시보드가 제시하는 정확한 DNS 레코드를 Cloudflare DNS에 설정한다. 초기에는 DNS only로 검증하고 이중 프록시·별도 캐시 규칙은 필요가 확인될 때 검토한다.
- **Workers 선택 시:** `workers.dev`로 먼저 검증하고, 필요하면 해당 Worker의 Custom Domain으로 기존 Cloudflare 관리 도메인을 연결한다.
- **OCI 선택 시:** Coolify 라우팅과 TLS를 구성하고 실제 서비스에 사용할 호스트만 연결한다.

공식 안내: [Vercel 도메인 추가](https://vercel.com/docs/domains/working-with-domains/add-a-domain), [Cloudflare DNS 프록시 상태](https://developers.cloudflare.com/dns/proxy-status/), [Workers Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/).

개발 IDE 호스트와 심사용 서비스 호스트는 역할이 다르다. 심사위원에게 `/absproxy/3000` 개발 주소를 제출하지 않는다. 사용자가 새 도메인을 결정하면 origin과 허용 도메인을 바꾸고 필요한 빌드를 다시 만든다.

## 배포와 자격증명

대표가 Vercel GitHub 앱을 필요한 저장소에 연결하고, 신뢰하는 브랜치만 운영 배포로 사용한다. 공개 외부 PR의 코드는 검토 전에 운영 키와 함께 실행하지 않는다. 프리뷰에 필요한 최소 키와 운영 키를 구분한다. [Vercel 공개 PR 배포 동작](https://vercel.com/docs/git)

KTO·LLM·DB 관리 키는 서버 환경 설정에서만 읽는다. API 요청의 `serviceKey`를 포함한 URL, HTTP 오류 객체, 전체 환경변수를 로그에 남기지 않는다. 브라우저 지도 키가 필요한 경우 공급자가 요구하는 허용 도메인 제한을 적용한다.

Firestore는 우선 서버 전용으로 접근한다. 실제 구현 때 관리 자격증명 부여 방식과 IAM 권한을 확인하며 공개 문서·예제 파일에 값을 넣지 않는다. 공모전의 인증키 제출은 공식 제출 경로에서 처리한다.

## 첫 배포 검증과 대안 전환

개발 첫날 반나절을 다음 검증에 배정한다. UI 레퍼런스 없이도 작은 진단 화면으로 가능하다.

1. Next 페이지·API·정적 파일이 code-server와 배포 루트에서 동작한다.
2. 공개 Org 연동 후 대표·팀원 커밋의 배포 흐름과 관리 권한을 확인한다.
3. Firestore에 자체 시험 문서 하나를 쓰고 읽고 지우며 자격증명이 브라우저에 없는지 확인한다.
4. 실제 관광 API의 인증·응답·소요시간과 키 마스킹을 확인한다.
5. 추출 공급자 설정이 가능해지면 실제 규정의 추출 시간·토큰·비용을 측정한다.

Vercel에 실제 제약이 생기면 Cloudflare에서 같은 작은 흐름을 검증한다. `next dev` 성공을 Workers 성공으로 간주하지 않고 `workerd`와 배포 후 CPU·메모리·응답을 본다. Next 앱을 정적 export로 바꾸는 것만으로 서버 API와 LLM 호출 문제가 해결되지는 않는다.
