Kakao Local의 공식 응답에 있는 장소명·주소·좌표·전화·상세 URL과, 지도 서비스 화면의 규정·후기 전체를 구분한다. Local API만으로 반려동물 규정 원문이 모두 제공된다고 전제하지 않는다.

추가 정보는 실제 확보 가능한 공식 안내나 이용이 허용된 경로부터 연결한다. 외부 페이지 대량 수집을 핵심 기능의 성립 조건으로 두지 않는다.

## 사용자 앱 조사 방식 (2026-09-12)

사용자의 군 복무 여건을 반영해 현장 방문·업체 연락을 필수 작업으로 두지 않는다. Codex는 공개 웹·공식 공지를 조사하고 사용자는 반려생활·네이버지도에서 장소별 안내 화면과 공유 링크를 확보한다. 첫 대상 4곳, 검색어, 주소, 부족한 조건과 자료 전달 방식은 [사용자 앱 조사 안내](INCHEON_APP_RESEARCH_GUIDE.md)에 있다.

앱 열람은 업체 직접 확인과 구분한다. 같은 KTO 자료의 재게시를 독립 근거로 계산하지 않으며, 미기재·충돌을 이용 가능으로 바꾸지 않는다. 캡처는 채팅 또는 Git 제외 `.cache/incheon/user-research/`에서 검수하고, 원출처·이용 조건을 확인하기 전 공개 저장소·서비스에 자동 반영하지 않는다. 이번 문서화는 신규 규정 확보나 제품 반영 완료 기록이 아니다.

- 데이터가 없는 조건을 제한 없음으로 처리하지 않는다.
- 현재 전체 장소 수·채움률·전화번호 상태로 재인용하지 않는다.

## 첫 데이터 점검과 지역 선정

인천을 첫 집중 검수 지역으로 확정했다. 현재 지원 업종 43곳 검색, 시 자료 9곳 연결과 표본 30곳 검사를 수행했다. 유효 대체 후보 확보는 아직 완료하지 못했으며 **실제 여행 목적을 유지하며 대체할 수 있는 후보 밀도**를 계속 검증한다. 상세 수치는 [인천 보강](INCHEON_COVERAGE.md)에 있다.

점검 항목:

1. 관광지·식당·카페별 동반 규정과 시간 정보의 충실도.
2. 체중·마릿수·이용 구역 규정의 명시성.
3. 가까운 같은 목적의 대체 후보 존재 여부.
4. 연락처와 공식 안내에 접근할 수 있는지.
5. 장소명·주소·좌표가 서로 다른 출처에서도 같은 업체를 가리키는지.
6. 최신 자료뿐 아니라 업종·수정 시점이 다양한 표본의 품질.

제안 목표:

- 집중 검수 장소 약 30곳.
- 대표 코스 3개.
- 주요 교체 대상별 대체 후보 2개 이상.
- 체중·마릿수·구역·준비물·운영시간 충돌을 포함하는 평가 사례.

목표는 확보 실적이 아니다. 데이터가 부족하면 권역이나 지원 업종을 조정하고, 유효 후보가 없는 결과도 정직하게 처리한다. 전국 검색과 집중 검수 품질은 별개로 표시한다.

## 조회·저장·운영

- 검색·검증 흐름에서 공사 API를 실제 호출하고 현재 원문을 기준으로 평가한다.
- 출처와 조회 시각을 사용자에게 표시한다.
- 원문·추출 규정·판정 이력의 장기 저장 및 캐시 허용 범위는 운영팀 안내로 확정한다. 파생 데이터라는 이유만으로 예외라고 간주하지 않는다.
- 저장 범위 확정 전 대규모 원문 DB 적재를 기본 아키텍처로 전제하지 않는다.
- API별 쿼터와 한 코스의 호출량을 측정하고 후보 수·호출 순서를 제한한다. 과거 호출 횟수는 현재 쿼터가 아니다.
- API 인증키는 서버 환경 설정으로 관리한다. 요청 URL·쿼리·오류 메시지에서 키를 제거한 뒤 로깅한다.
- LLM에는 규정 해석에 필요한 정보만 전달하고 자격증명을 전달하지 않는다.
- 외부 API 실패 시 미확인 상태와 재시도 방법을 표시한다. 가짜 최신 응답이나 성공 결과를 대신 제공하지 않는다.
- 저장·공유 기능을 구현할 때에는 판정 시점과 재검증 필요성을 표시한다.

## 구현 전 확정할 사항

채택한 DB는 Firestore Spark이며, Cloudflare로 전환할 경우 D1을 검토한다. 이 선택은 KTO 데이터의 장기 보관 허용 여부를 바꾸지 않는다. 초기에는 현재 요청의 원문·추출 규정과 서버에 저장할 자체 데이터를 구분하고, 원문과 파생 규정의 요청 간 캐시·영구 적재는 기본 비활성으로 설계한다. 구체적인 저장 경계는 [아키텍처](../engineering/ARCHITECTURE.md), 무료량은 [기술 스택](../engineering/STACK_DECISION.md)을 따른다.

- 현재 KTO 응답과 정확한 엔드포인트별 계약.
- 추가 데이터 원본과 이용 조건.
- 집중 지원 지역·업종·실제 후보 목록.
- 장기 저장·캐시·파생 규정 보관 범위.
- 지도·이동시간 API의 권한, 쿼터, 예상 비용.
- 장소 병합 기준과 출처 충돌 처리 절차.
- 조건별 재확인 기준과 운영 주체.

## 인천시 보완 자료의 보관 경계

2026-09-11 원본 CSV의 이용허락범위 제한 없음을 확인하고 선택한 9행을 저장했다. KTO 원문과 파생 규정은 계속 매 요청 조회·추출하며 영구 저장하지 않는다. 시 자료와 KTO는 독립 추출하고 구역별 충돌을 미확정으로 남긴다. 발행일·열람일·업체 확인일을 구분하며, 갱신 예정일 경과 시 재검수 없이 자동 적용하지 않는다. [인천 보강 기준](INCHEON_COVERAGE.md)을 따른다.


## 인증된 계정 노트 (2026-09-12)

사용자가 명시적으로 저장한 제목·반려견 프로필·일정·방문지 ID와 선택 조건만 Firestore에 저장한다. 원문·장소 설명·사진·파생 규정·판정 결과는 제외한다. 기기 저장을 로그인 시 자동 이전하지 않으며 계정 노트를 불러오면 현재 API로 다시 검사한다. 인증·소유권·보관 개수와 삭제 흐름은 [계정 저장 기준](../engineering/FIREBASE_AUTH_AND_STORAGE.md)을 따른다.
