# 의사결정 및 이전 대화 히스토리

정리일: 2026-09-10\
입력 자료: 사용자가 붙여 준 과거 ChatGPT 대화, 최초 요청의 공모전 안내·제출 아이디어, 2026-09-10 기획 제안과 사용자 승인.

이 문서는 대화 전문의 보관본이 아니라 **결정과 근거의 요약**이다. 대화에 포함된 API 인증키는 의도적으로 제외했다.

## 1. 공모전 참가와 주제 탐색

사용자는 생활관 선임과 2인 팀으로 웹·앱 구현 부문에 참가하고, 10개 지정과제 중 독창적이며 실제 구현 가능한 아이디어를 탐색했다. 초기 요청에는 전년도 수상작과 대회 관계자 발언을 분석해 주제를 추천해 달라는 의도가 있었다.

현재 상태는 사용자 설명상 예비 아이디어 제출을 통과했으며 제품 구현을 준비하는 단계다. 당시 공고 PDF·검증 키트·결과 파일은 현재 작업 공간에서 확보하지 못했다.

## 2. PawProof 초기 방향

이전 대화는 PawProof를 여행 코스 전체의 성립 여부를 검증하고 실패 지점만 복구하는 서비스로 제안했다.

초기 핵심 조합:

- 3~5개 방문지의 규정 동시 검사.
- 코스에서 문제가 되는 장소 특정.
- 같은 유형의 장소로 교체.
- 교체 전후 추가 이동시간 표시.
- 판정 원문·출처·시점 표시.
- 실제 규정에서 준비물 생성.

당시 제외 제안: 일반 지도 중심 서비스, 숙소 예약, 커뮤니티, 예방접종 PASS, AI 여행 챗봇, 자동 전화.

## 3. 데이터 후보와 시연 지역

이전 대화는 KTO 전국 데이터에 인천 집중 시연 지역을 결합하고, 인천 CSV·식품안전나라·문화정보원·Kakao Local·Kakao Directions를 보완 데이터로 제안했다.

스키마·행 수 확인과 실제 원본 품질 검증은 서로 다른 상태였다. 현재 이 기록은 [데이터 전략](../data/DATA_STRATEGY.md)에 구분해 보존한다. 인천을 이미 고신뢰 지역으로 검증했다고 간주하지 않는다.

## 4. 서비스명 결정

이전 대화는 해외의 유사 이름 앱을 이유로 PawProof를 코드명으로 두고 ‘반려완주’를 제출명으로 제안했다.

**사용자는 PawProof 이름을 그대로 사용하기로 명시적으로 결정했다.** 현재 서비스명은 PawProof(포프루프)이며 이름 변경을 전제로 기획하지 않는다. 이 결정은 별도의 상표·권리 검토 완료를 뜻하지 않는다.

## 5. 과거 API 검증 요청과 보고

사용자는 KTO 개발계정 승인을 받은 뒤 인증키를 제공하고 직접 데이터 검증을 요청했다.

이전 답변은 91회 호출·오류 0건, 최신 수정순 30개 장소, 체중 2건·마릿수 1건 등 결과를 보고했다. 키를 명령어·로그·결과 파일에 저장하지 않았다고도 설명했다.

현재 문서화 과정에서는 이를 **과거 대화의 보고**로 취급한다. 원응답·검증 리포트를 확보하거나 호출을 재현하지 않았으며, 당시 보관 방식까지 독립적으로 확인한 것은 아니다.

현재 구현에 가져올 판단:

- 규정 추출→규칙 판정→근거 표시 구조를 유지한다.
- 누락은 제한 없음으로 해석하지 않는다.
- 반복 필드와 문맥을 함께 검토한다.
- 전화번호와 숙박 규정은 별도 검증이 필요하다.

## 10. 2026-09-10 개발·운영 기획

사용자는 무료 호스팅을 우선하고 Vercel·Firebase·Next.js를 제시했다. 보유 도메인은 Cloudflare DNS에서 관리하는 `hothyun.com`이며, 새 도메인 구매는 직접 결정하고 디자인 레퍼런스도 직접 제공하기로 했다.

현재 개발 환경은 사용자 설명상 OCI의 Coolify에서 호스팅한 code-server다. 프록시를 통한 개발과 루트 경로 배포를 환경변수·공통 유틸로 분리하고, 클린 코드·클린 아키텍처·단일 책임 원칙을 따르도록 요청했다.

후속 확인에서 GitHub **Organization의 공개 저장소**를 사용한다고 밝혔다. Vercel이 무료로 맞지 않으면 Cloudflare Workers도 허용 가능한 대안으로 제시했다.

이번 공식 문서 검토에 따른 권고:

1. 공개 Org 저장소는 비공개 Org에 적용되는 Vercel Hobby 제한과 구분한다. Next.js + Vercel Hobby + Firestore Standard/Spark를 우선 검증한다.
2. Hobby의 개인·비상업 용도 조건과 실제 배포 연동은 별도 확인한다. 무료 대시보드 팀 권한이 GitHub 협업과 같다고 가정하지 않는다.
3. Firestore만 DB로 사용하고 Firebase Functions·Storage·App Hosting의 결제 계정 요구를 혼동하지 않는다.
4. Supabase의 비활동 일시정지와 Workers Free의 요청당 CPU 제한을 비교에 반영한다.
5. Cloudflare로 전환하면 Next.js + OpenNext + D1을 검증하되, 현재 Cloudflare 신규 앱 안내의 vinext 베타 권고와 구분한다.
6. `/proxy`는 접두사를 제거하므로 `/absproxy`와 Next `basePath`를 맞추는 개발안을 권고한다. 배포는 루트 경로로 별도 빌드한다.
7. 규칙 도메인과 사용 사례를 외부 SDK·호스팅·DB에서 분리한다.
8. 기존 기획 문서를 목적별 폴더로 옮기고 개발·운영 문서를 추가한다.

LLM 비용 범위 질문은 아직 답변받지 않았다. 문서 작성은 진행하되 유료 공급자 사용을 승인된 것으로 취급하지 않았다. 이 기록은 기획 결과이며 실제 코드 구현·API 재검증·DNS 변경·배포를 의미하지 않는다.

## 11. 2026-09-10 기본 스택 채택과 1인 개발 규칙

## 12. 2026-09-10 초기 구현 착수

사용자는 보유 OpenRouter 크레딧을 LLM API 호출에 사용하는 방향을 제시했다. 배포·DB 연결 준비는 직접 담당하고 디자인 레퍼런스는 추후 제공한다. KTO 반려견 API 사용 요청도 남겼다고 설명했다. 이는 현재 계정의 승인·실응답을 확인한 결과와 구분한다.

첫 구현 범위는 Next.js 초기화, 환경변수 검증, code-server·배포 경로 유틸이다. 서비스 본 기능·외부 API 호출·DB 연결·외부 배포는 이번 범위에 포함하지 않는다. Next.js 16.3.4, React 19.3.0, TypeScript 5.9.3, pnpm 12.3.4를 고정하고 최소 시작 화면·소개·상태 확인 API로 기반을 구성한다.

사용자 요청으로 Firebase Authentication과 Firestore를 연결하는 공통 모듈을 추가한다. Web 공개 설정과 Admin 자격증명을 분리하고, API에서 검증한 UID로만 사용자 경로에 접근한다. 브라우저 직접 DB 접근은 기존 설계대로 거부한다. 자체 사용자 입력만 최대 20개 저장하며 원문/파생 규정/판정 결과는 제외한다. 트랜잭션으로 개수와 revision 충돌을 검사한다. 실제 연결 키가 없는 상태에서는 준비 중으로 안내하고, 인증·Firestore 에뮬레이터를 demo 프로젝트에서 검증한다.

## 31. 2026-09-12 로그인과 계정 노트 UI

Google 및 이메일 로그인/가입/인증/재설정/로그아웃을 공통 계정 Dialog에 제공한다. 비로그인 검사와 기존 기기 저장을 유지하며 로그인은 자동 업로드를 일으키지 않는다. 계정 저장·목록·입력 불러오기·수정·삭제는 별도 패널에서 제공하고 입력 교체/삭제는 확인한다. 로그아웃 시 계정 목록을 제거하되 현재 편집과 기기 저장을 유지한다고 고지한다. 실제 OAuth·메일 도착·Firebase 프로젝트 연결은 환경 설정 후 별도로 검증한다.


## 32. 2026-09-13 실제 Firebase 연결·비밀번호 10자 기준

사용자가 환경변수를 입력하고 실연결 점검을 요청했다. 임시 사용자·노트만 사용하는 별도 opt-in Playwright 스크립트로 실제 Auth와 Firestore의 로그인·저장 흐름과 직접 DB 접근 차단을 확인하고 정리했다. 사용자 Firebase 비밀번호 정책은 10자 이상이며 UI 입력 제한과 문구도 이에 맞춘다. 실제 Google 동의·메일 도착·설치 PWA는 별도 검증 대상으로 유지한다.


## 33. 2026-09-13 계정 UX·반려견 프로필·여행 자동 복원

사용자가 로그인 모달 단순화, 로그인 후 여행 화면 이동과 토스트, 독립 프로필/반려견 등록, 로그인 사용자 여행 자동 저장, 실제 장소·검사 기록 복원, 검색 전 후보·최근 기록을 요청했다. 프로필과 여행 입력의 생명주기를 분리하고 저장 당시 검사 요약을 최신 판정과 구분한다. 규정 원문·인용·LLM 규칙은 저장하지 않는다. 과거에 기록하지 않은 검사 결과는 복구한 것처럼 표시하지 않는다. 상세 구조와 검증 범위는 Firebase 기준/구현 기록을 따른다.

## 34. 2026-09-13 헤더 아바타·로그인 모달 간소화

사용자 피드백에 따라 계정 링크를 헤더 맨 오른쪽 원형 아바타로 바꾸고 /profile로 직접 이동한다. 로그인 복원 중 버튼을 비활성화하며 인증된 사용자의 AuthDialog는 열리지 않는다. 계정 사진은 Radix Avatar로 표시하고 사진 부재·오류에는 이름/이메일 첫 글자를 사용한다. 로그인 방식 사이의 문구를 제거해 1px 녹색 선만 두고, 회원가입·비밀번호 찾기는 중앙 정렬과 충분한 간격을 유지한다.

## 35. 2026-09-13 Production 환경변수 템플릿

사용자가 API 키만 채워 배포할 수 있도록 .env.example을 Vercel Production 기본값으로 정리했다. Corepack·운영 프로필·PWA·실 API 활성화·기존 모델 ID는 채우고 API 키와 Firebase 프로젝트별 값 10개는 비워 둔다. 운영 경로와 선택 origin의 빈칸을 구분하고 개발 전용 설정을 제외했다. 실제 값은 Vercel 또는 비추적 사본에 넣으며 기존 로컬 설정은 변경하지 않는다.

## 36. 2026-09-13 Vercel 의존성 설치 정책 보완

Vercel에서 보고된 ERR_PNPM_IGNORED_BUILDS는 firebase-tools → superstatic의 선택적 re2 빌드 정책 누락으로 확인했다. pnpm-workspace.yaml에 re2: false를 추가해 불필요한 네이티브 빌드를 생략하며 전체 스크립트 제한은 유지한다. 별도 임시 복사본에서 Node 24.15.0·pnpm 12.3.4로 기존 설정의 동일 오류를 재현했고, 수정 후 node_modules가 없는 상태의 frozen-lockfile 설치·운영 빌드(TypeScript 포함)·Firebase CLI 15.30.0 실행·superstatic의 JavaScript RegExp 대체 동작을 확인했다. 실제 키·기존 개발 서버 설정은 변경하지 않았다. Vercel의 수정 커밋 배포와 실 API 연결 검증은 이 검사에 포함하지 않는다.

## 37. 2026-09-13 iPhone PWA OAuth 포커스와 배포 운영

iPhone Safari 설치 PWA에서 Google 이메일 입력 시 키보드가 뜨지 않는 제보를 받았다. 앱 모달을 유지한 채 OAuth 창을 열던 흐름을 수정해 포커스/스크롤 잠금을 먼저 제거하고 클릭 전 준비된 Auth SDK를 사용한다. iOS의 창 닫기 미감지에는 잠금 없는 대기 종료 버튼을 제공하며 요청 식별자로 재시도 경합을 막는다. Firebase authDomain과 로그인 프로토콜은 유지한다. 자동화의 앱 포커스 검사와 실제 iPhone 키보드 확인을 구분한다.

사용자는 검증 후 main 푸시와 Vercel 자동 배포를 승인했다. AGENTS.md와 코드·배포 기준 문서에 이를 반영하며 기존 문서의 미배포 상태를 갱신했다. 상세 검증 결과·남은 사항은 delivery/WORK_LOG.md에 기록한다.


## 38. 2026-09-13 브라우저 요청 취소 호환성

배포 버전의 반려견 프로필 조회·인천 검색에서 `AbortSignal.any is not a function` 제보를 받았다. 두 클라이언트 API가 취소 신호와 시간 제한을 합칠 때 신규 정적 메서드를 무조건 호출해 네트워크 요청 전에 실패한다. Next.js의 기본 Safari 16.4+ 지원 범위와 달리 `AbortSignal.any()`는 [Safari 17.4에서 추가](https://webkit.org/blog/15063/webkit-features-in-safari-17-4/)되었으므로 브라우저 API를 무조건 전제하지 않는다. 공통 AbortController 기반 요청 범위를 사용하고 기존 시간 예산·취소를 유지한다. 정적 메서드를 제거한 Chromium·Firebase 에뮬레이터 검사와 실제 사용자 기기 검증은 구분한다. 상세 결과는 [작업 로그](../delivery/WORK_LOG.md)에 기록한다.


## 39. 2026-09-13 계정 전용 저장과 상단 여행 노트

사용자는 비회원 기기 저장을 없애고 로그인·계정 자동 저장으로 유도하며, 노트 제목/목록을 편리하게 재배치하도록 요청했다. 비회원 코스와 검사 결과는 메모리 전용으로 유지하고 편집 후 새로고침/탭 닫기에는 브라우저 기본 확인창을 요청한다. 사용자 정의 문구·모바일 강제 종료까지 제어할 수 있다고 표현하지 않는다.

회원의 제목·자동 저장 상태·목록·새 노트를 여행 상단으로 옮기고, 검색 가능한 모달에서 정상 노트를 즉시 연다. 삭제/저장 실패 초안 폐기만 확인한다. 현재 비회원 입력은 로그인 후 계정으로 이어가되 이전 기기 저장 데이터는 읽거나 옮기지 않는다. 계정 변경은 이전 편집 상태와 note URL을 비워 계정별 소유 경계를 유지한다. 이메일 인증과 서버 저장 경계는 유지한다.
